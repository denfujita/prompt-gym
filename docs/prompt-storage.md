# Prompt and trajectory storage

## What is implemented

PostgreSQL is the operational source of truth. A submitted coaching prompt is trimmed, then creates one immutable `turn` and one hash-linked `turn.queued` event in the same transaction. The worker rebuilds visible conversation state from those events and records provider-reported usage separately.

Every event, usage item, and verification generated by a turn now carries the same nullable `turn_id`. `EpisodeV1` preserves that link. This makes a trajectory joinable without timestamps or text matching:

```text
attempt
  -> turn (human prompt)
      -> run_event (model, tool, and task activity)
      -> usage_item (provider tokens and actual cost)
      -> verification_run (reward and verifier digest)
```

This is the minimum useful unit for lab data: one human instruction, the resulting behavior, its exact cost, and its reward.

The Benchmark Lab target adds `benchmark_evaluation` as a separate turn-linked projection for candidate, correctness, performance metric, and token checkpoint. It is not implemented yet and remains distinct so an iterative candidate check cannot masquerade as terminal verification.

## Current privacy gap

The alpha still stores the raw prompt in three PostgreSQL values: `turn.prompt`, the serialized `turn.state`, and the public payload of `turn.queued`. Those rows are deleted through the account-deletion cascade and export code redacts common PII and secret patterns, but the application does not yet provide field-level prompt encryption or the promised 30-day quarantine deletion.

Public replay currently returns the same unsanitized event payloads to an authorized owner or a post-season viewer with replay consent. Ranked production, public replay publication, and commercial export must remain gated until prompt duplication is removed and replay-specific redaction is enforced.

## Target prompt vault

Keep `turn` as the lineage record, but move raw text into one encrypted prompt object:

```text
prompt_id                 UUID
turn_id                   UUID UNIQUE
ciphertext                BYTEA
nonce                     BYTEA
key_version               TEXT
prompt_hmac               TEXT
character_count           INTEGER
submitted_at              TIMESTAMPTZ
quarantine_expires_at     TIMESTAMPTZ
scan_status               pending | clean | quarantined | redacted
consent_recorded_at       TIMESTAMPTZ
research_permitted        BOOLEAN
deletion_state            active | withdrawn | deleted
```

- Encrypt with envelope encryption using a managed KMS key; use a unique data key and nonce per prompt.
- Use a keyed HMAC of normalized text for duplicate detection. Do not expose an ordinary hash that permits dictionary attacks.
- Store no raw text in `turn.state` or `run_event.public_payload`; store only `turn_id`, ordinal, counts, and safe display metadata.
- Hydrate the owner's visible replay from the prompt vault at the API boundary. Workers decrypt only while constructing the active model request.
- Keep model/tool events, provider usage, and verifier outcomes independently immutable and hash-linked.

## Retention and export

1. Operational processing is required to run and score the attempt.
2. Raw prompt ciphertext expires after at most 30 days, even when research consent exists.
3. PII, secret, path, URL, and near-duplicate scans run before any research staging.
4. A separately stored redacted research copy is created only for active, optional consent and an exact reproducible solve.
5. Public replay consent is independent from research consent.
6. Withdrawal prevents future releases and creates buyer-facing tombstones. Account deletion destroys prompt objects and their wrapped data keys.
7. Released episodes retain `turn_id`-scoped pseudonymous lineage, never account, IP, device, hidden seed, verifier source, or private reasoning.

## Migration order

1. **Done:** add explicit turn lineage to events, usage, verification, and `EpisodeV1`.
2. Add the prompt-vault table, KMS adapter, retention job, and scan state machine.
3. Dual-write encrypted prompt objects while retaining the old columns for rollback.
4. Backfill existing alpha prompts, verify decrypt/replay, then stop writing prompt text into events and JSON state.
5. Drop the legacy plaintext columns only after account deletion, SSE resume, worker restart, and export replay tests pass.
6. Enable Grade-A export only after retention and tombstone propagation pass an external audit.
